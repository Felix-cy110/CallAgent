# CallAgent 产品计划

更新日期：2026-11-23。此计划来自项目所有者的明确要求，是后续开发的范围依据。

## 产品定位

将 Tutti 的 `@session` 能力抽取为端侧 Client Skill，让不同 Agent 的已有会话可以相互引用上下文，并在用户明确要求时向指定会话发送消息。只做 session，不做其他 `@` 功能。

支持对象固定为 **Claude Code、Codex、WorkBuddy 的 Desktop 会话**。CallAgent 是在用户本机后台运行的 Client，无 GUI，使用 **C++20、CMake、libhv**。通过各桌面端的 Skill 入口调用，原生会话发现、详情读取和投递由 Client 的适配器负责。

## AT 入口

用户通过桌面端 Skill 菜单调用一个固定的 AT 入口，由 Agent 查询 Client 并展示会话候选。候选形如 `AT codex 手机端小小优化`，session 名超过 10 个可见字符截断；每种 Agent 取最近活跃的 3 个，共最多 9 个，不足时显示实际数量。用户已明确目标时直接匹配，有歧义时再选择。选定后使用完整稳定 key，不能因排名变化切换目标。

当前将“最活跃”默认解释为最近对话活动时间。展示、稳定身份、发布更新及三端 IPC 的源码依据见 [本机桌面与 AT 设计](desktop-at-design.md)。宿主菜单中固定 AT 的实际显示与加载需逐端验收；候选在对话中查询，不依赖菜单动态生成子项。

## 三个阶段

| 阶段 | 连接范围 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 1 | 用户同一台电脑 | 三种 Agent 的已有会话发现、引用、读取，以及明确授权后的互相发消息 | 当前唯一开发阶段 |
| 2 | 同一局域网的不同电脑 | 在阶段 1 的会话能力上增加跨设备发现与连接 | 后续，不实现 |
| 3 | 配置同一公网服务的电脑 | 已连接该公网服务的电脑之间访问授权开放的会话 | 后续，不实现 |

第 3 阶段指接入用户配置的服务的电脑，不是扫描或访问互联网任意电脑。身份、设备配对和访问控制在对应阶段细化。本阶段不实现局域网广播、公网服务、远程注册、连接配置或远程传输。

## 第一阶段工作拆分

1. **抽取 Skill（已完成）**：独立规则包保留会话引用和向已有会话投递的语义；现已更新为实际 CLI 命令。
2. **原生适配（代码与协议测试已完成）**：参考 ObeingWorkspace，接通 Codex app-server + Desktop owner IPC、Claude 注册/只读 transcript/peer IPC 与接收插件、WorkBuddy 只读目录 + 认证 Local RPC。
3. **本机运行时与 AT 发布（已实现）**：单个后台 Client、CLI、稳定身份、每端 Top 3、十个可见字符截断、持久化防重与回执、每个宿主一份固定 AT Skill、运行时查询候选、旧包迁移、所有权检查和原子替换。
4. **实机交互验收（未完成）**：三端真实发送、六个有向跨 Agent 组合、同端跨会话，以及 Skill 菜单的实际名称和加载机制需要受控会话验证。

2026-11-23 本次实现首先覆盖 macOS ARM64。四个 CTest 测试组验证业务规则、原生协议模拟、WorkBuddy 守护和 Claude 插件行为，未向真实用户会话发送测试消息。构建、启动及能力边界见 [运行时文档](runtime.md)。

## 第一阶段验收边界

- 能发现本机三种 Desktop 的已有会话，返回可区分 Agent、账号/配置实例和原生 ID 的身份；同名或跨 Agent 相同 ID 不串会话。
- 每个宿主只有一个 AT Skill，调用时呈现每端最近活跃的最多 3 个 session，共最多 9 个候选；零候选仍保留入口。标题截断、排名更新不会改变已选目标身份，列表刷新不改写 Skill。
- 从任一种 Agent 中引用另一种 Agent 的会话时，按需读取上下文，保留角色、顺序、来源及截断信息。
- 仅引用不触发执行；用户明确要求发送时，将消息投递到指定已有会话，得到真实回执，按需等待对应结果。
- 对只读、运行中、已删除、不可访问的会话给出准确能力或状态，不伪造成功，不重复发送无法确认送达的消息。
- 无 GUI，不要求 Tutti 运行，不创建 Agent，不扩展到其他 `@` 能力或其他设备。
- Claude Code ↔ Codex、Claude Code ↔ WorkBuddy、Codex ↔ WorkBuddy 六个有向跨 Agent 组合，以及三种 Agent 各自不同会话间的引用/投递都需要后续实测；当前未验证。

## 实际适配状态

| 对象 | 代码与模拟协议验证 | 实机状态与剩余验收 |
| --- | --- | --- |
| Codex Desktop | 目录、owner 核实、最近文本、定向 start-turn、回执与完成状态 | 只读实机探测已发现 3 个 Desktop-owned 会话；真实投递、继承桌面设置和 AT 菜单待验收 |
| Claude Desktop Code | 注册、父链 transcript、peer credential、Mods 插件提交、接收回执、防重复 | 本机没有可用的 Desktop session 注册；当前尚未验证 macOS 原生插件加载和真实发送；回执不提供任务完成关联 |
| WorkBuddy Desktop | macOS 安装发现、已有桌面自动带端口重启、生命周期与互斥测试；当前账号目录、进程身份校验、v2 HMAC、会话读取、投递与回执、连接复用 | macOS WorkBuddy 5.11.3 只读实机探测已通过认证并发现 9 个本地会话，取其中 3 个作为候选；自动接管已通过隔离进程测试，真实桌面重启、消息投递和 AT 菜单待验收 |

AT 包的内部 `name` 为 `at`，Codex `display_name` 为 `AT`。每份包使用同一操作规则，按运行配置填入可执行文件和配置绝对路径，携带许可证与 NOTICE。旧动态包仅在所有权和内容校验通过后清理；旧命令仍可使用原完整 key。当前状态继续返回 `menuVerification: not_verified`，不承诺宿主的大小写显示或原生动态子菜单。

当前每端配置一个实例，读取只提供最近文本摘要，不提供附件和任意历史分页。Windows 尚未实现，Linux 未验证；不把跨平台目标写成已支持能力。阶段 2、3 保持不实现。
