# CallAgent 产品计划

记录日期：2026-11-22。此计划来自项目所有者的明确要求，是后续开发的范围依据。

## 产品定位

将 Tutti 的 `@session` 能力抽取为端侧 Client Skill，让不同 Agent 的已有会话可以相互引用上下文，并在用户明确要求时向指定会话发送消息。只做 session，不做其他 `@` 功能。

支持对象固定为 **Claude Code、Codex、WorkBuddy**。其他 Agent 不在当前范围。CallAgent 自身无 GUI，使用 **C++20、CMake、libhv**。不修改桌面应用输入框，也不承诺通过 Skill 自动增加原生 `@` 选择器；会话发现和操作通过各宿主实际提供的能力接入。

## 三个阶段

| 阶段 | 连接范围 | 目标 | 当前状态 |
| --- | --- | --- | --- |
| 1 | 用户同一台电脑 | 三种 Agent 的已有会话发现、引用、读取，以及明确授权后的互相发消息 | 当前唯一开发阶段 |
| 2 | 同一局域网的不同电脑 | 在阶段 1 的会话能力上增加跨设备发现与连接 | 后续，不实现 |
| 3 | 配置同一公网服务的电脑 | 已连接该公网服务的电脑之间访问授权开放的会话 | 后续，不实现 |

第 3 阶段指接入用户配置的服务的电脑，不是扫描或访问互联网任意电脑。身份、设备配对和访问控制在对应阶段细化。本阶段不实现局域网广播、公网服务、远程注册、连接配置或远程传输。

## 第一阶段工作拆分

1. **抽取 Skill（本次）**：保留会话引用和向已有会话投递的操作语义；去除其他 mention、Tutti UI 和模板依赖；记录来源及接入边界。
2. **核实原生适配**：逐一验证三种 Agent 桌面端的会话发现、历史读取、投递与状态/结果获取通道，记录平台和版本。CLI/SDK 能管理会话不等于能控制桌面端正在打开的原生会话。
3. **实现本机运行时**：用 C++20/CMake/libhv 实现统一的会话入口与适配器；接入真实能力后再把具体 CallAgent 命令写进 Skill。
4. **本机联调**：用受控测试会话验证跨 Agent 的引用和定向投递，确认已有会话身份、消息顺序、回执与结果关联。

本次完成第 1 项；它不代表第一阶段全部交付。现有 `callagent` 可执行文件仍是输出版本的工程骨架。

## 第一阶段验收边界

- 能发现本机三种 Agent 的已有会话，返回可区分 Agent 和原生 ID 的身份；同名或跨 Agent 相同 ID 不串会话。
- 从任一种 Agent 中引用另一种 Agent 的会话时，按需读取上下文，保留角色、顺序、来源及截断信息。
- 仅引用不触发执行；用户明确要求发送时，将消息投递到指定已有会话，得到真实回执，按需等待对应结果。
- 对只读、运行中、已删除、不可访问的会话给出准确能力或状态，不伪造成功，不重复发送无法确认送达的消息。
- 无 GUI，不要求 Tutti 运行，不创建 Agent，不扩展到其他 `@` 能力或其他设备。
- Claude Code ↔ Codex、Claude Code ↔ WorkBuddy、Codex ↔ WorkBuddy 六个有向跨 Agent 组合，以及三种 Agent 各自不同会话间的引用/投递都需要后续实测；当前未验证。

## 尚待核实

| 对象 | 本次确认范围 | 后续核实内容 |
| --- | --- | --- |
| Claude Code | Tutti 有运行时接入与外部历史导入代码 | 目标桌面环境的发现、读取、已有会话投递与同步方式 |
| Codex | Tutti 有 app-server 接入与外部历史导入代码 | 原生桌面会话与可用接口的对应关系、活动会话投递行为 |
| WorkBuddy | 在本次固定的 Tutti 源码快照中未找到该名称的适配 | 官方可用接口、会话身份、历史读取、投递及 Skill 加载方式 |

目标支持列表与已验证能力必须分开记录；没有适配器时 Skill 应明确报告不可用。操作系统覆盖范围尚未指定，不能因本次在 macOS 上整理材料就宣称 Windows/Linux 已验证或将产品限制为 macOS。
